# Claims & receipts

Every claim this repository makes about the baseline-vs-governed contrast is
backed by a command you can run and an artifact you can read. This page is the
receipts index: the claim, the number, where the number comes from, and how to
reproduce it.

> Reference architecture and learning repository — **not** production security
> software. The tools and data are synthetic and the model is a deterministic
> offline stand-in, so these numbers are a **reference contrast**, not a security
> benchmark or a production guarantee.

## Reproduce everything

All receipts are produced offline, with no API keys, by:

```bash
make setup   # install (only runtime dependency: pydantic)
make demo    # baseline-vs-governed contrast; regenerates the trace artifacts
make eval    # offline router/policy evaluation gate
make test    # the full unit suite that pins these behaviors
```

## The before/after scorecard

`make demo` runs the **same** refund case (`C-100` / `INV-9`) through both paths
and writes a generated scorecard to
[`traces/comparison_scorecard.md`](traces/comparison_scorecard.md) (and `.json`).
The numbers are computed from the live runs, not hand-written:

| Dimension | Baseline | Governed | Receipt |
|---|---|---|---|
| tools exposed to the model | 9 | 5 | shortlist in [`catalog.py`](enterprise_agent_control_plane/catalog.py) |
| approx model-visible context (chars) | 1290 | 108 | `context_reduction` in [`catalog.py`](enterprise_agent_control_plane/catalog.py) |
| raw sensitive fields in model context | 14 | 0 | bounded Frames in [`frames.py`](enterprise_agent_control_plane/frames.py) |
| ungated write/destructive actions | 1 | 0 | policy gate in [`policies.py`](enterprise_agent_control_plane/policies.py) |
| policy decisions recorded | 0 | 1 | `AgentFencePolicy` in [`policies.py`](enterprise_agent_control_plane/policies.py) |
| structured audit trace | none | yes | `AuditTrace` in [`audit.py`](enterprise_agent_control_plane/audit.py) |

Gated action: `billing.issue_refund` → **approval_required**.

## Generated trace artifacts

These files are regenerated by the demo/baseline runs and are safe to inspect:

- [`traces/unsafe_run.json`](traces/unsafe_run.json) — the audit-light baseline run
  (refreshed by `make baseline`).
- [`traces/governed_run.json`](traces/governed_run.json) — a governed run's structured,
  hash-chained audit trace.
- [`traces/comparison_scorecard.json`](traces/comparison_scorecard.json) /
  [`.md`](traces/comparison_scorecard.md) — the side-by-side scorecard above.
- [`lessons/reviewed_lesson.json`](lessons/reviewed_lesson.json) — a human-reviewed lesson
  artifact from the lesson-capture lane.

## Baseline vs governed, dimension by dimension

The full mapping — each baseline gap, the governed control that closes it, the
dgenio library it maps to, and the exact code path — lives in the
[control traceability matrix](docs/control-traceability.md). That matrix is
validated in CI (`scripts/check_traceability.py`) so its claims cannot quietly go
stale. How realised each library integration is (stub vs real package) is the
[integration maturity matrix](docs/maturity-matrix.md).
